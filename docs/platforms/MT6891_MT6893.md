# MT6891 / MT6893 (chopin, ares) platform

Trạng thái: **build-only**. Chưa có thiết bị MT6891/MT6893 nào được kết nối
trong quá trình làm, nên không có mục nào dưới đây được xác nhận bằng phần cứng
thật. Tài liệu này phân biệt rõ "đã có driver + cấu hình + code" với "đã chạy
trên máy".

## Nguồn

| Thành phần | Nguồn |
| --- | --- |
| Nhân | `github.com/MT6891-Mainline/linux`, nhánh `7.3.3-mt6893-xiaomi-chopin` |
| Tham khảo SoC/thiết bị | `github.com/seriaTvT/kernel_mt6893` (chopin/ares, KVM) |
| Tham khảo cách port DRM vendor | `github.com/MT6895-Mainline/linux` |
| Shell Wayland tuỳ chọn | `github.com/denialwm/denial` |

Nhánh nhân trên là Linux 7.3.3 + driver MediaTek downstream, không phải nhân
QEAFIVELS tự viết. Đây là track nghiên cứu build-only của QEAFIVELS Linux Core,
không phải OS có nhân tự viết và không phải đường sản xuất Violet đã chọn
Linux 4.14.215. Không có bằng chứng boot hoặc hỗ trợ phần cứng MT689x.

## Cấu trúc trong repo

```

  mt689x_bringup.c/.h      mount vendor/firmware read-only, load module, đọc accel
  mt689x_wifi.c            trạng thái Wi-Fi cho verb `wifi` của QEAFRESCUE
  mt689x_session.c/.h      chạy Denial nếu có, fallback về shell QEAF
  main_mt689x.c            PID 1
  kernel/qeaf_mt689x.fragment   config bổ sung trên chopin_defconfig

  build_mt689x_kernel.py   gọi build nhân trong WSL/Linux
```

Phần dùng chung với violet (không fork source): `drm_kms.c`, `panel_scale.c`,

(`channel/fs/*`), toàn bộ LVGL shell trong `platform/violet/ui/`. Chỉ các file
gắn cứng phần cứng violet được thay bằng bản MT689x.

## Ma trận hỗ trợ

| Hạng mục | Driver / đường đi | Cấu hình | Trạng thái thực tế |
| --- | --- | --- | --- |
| UFS | `ufs-mediatek.c` (driver `ufshcd-mtk`), node `11270000.ufshci` | `SCSI_UFSHCD=y`, `SCSI_UFS_MEDIATEK=y`, `PHY_MTK_UFS=y` | Có driver + DTS + config; chưa boot |
| USB | MTU3 (`mediatek,mt6885-mtu3`, `dr_mode = "otg"` + extcon) + MT6360 Type-C (`mt6360-tcpc`), gadget configfs | `USB_MTU3=y`, `USB_MTU3_DUAL_ROLE=y`, `TYPEC_MT6360=y`, `USB_CONFIGFS=y`, `USB_CONFIGFS_MASS_STORAGE=y` | Có driver + gadget LUN; chưa cắm cáp |
| Màn hình DRM | `DRM_MEDIATEK_V2`; node `l16_36_02_0b_dsc_vdo,lcm` (k10a tắt) do `panel-k10a-bringup.c` xử lý | `DRM_MEDIATEK_V2=y`, `DRM_PANEL_K10A_36_02_0A=y` | Có driver + DTS + UI; chưa xuất hình |
| Cảm ứng | Novatek NVT SPI (`ts_novatek@0`) | `TOUCHSCREEN_NOVATEK_NVT_TS=y` | Có driver; chưa chạm |
| Wi-Fi | `mediatek,wifi`, driver `wlan` + `mtk_conninfra` | `MTK_COMBO=y`, `MTK_COMBO_WIFI=y` | Built-in trong Image; **cần firmware từ dump stock**; image chưa có WPA supplicant |
| Tần số quét cao | `lcm_get_modes` liệt kê 30/48/50/60/120 Hz, mode 120 Hz mang `DRM_MODE_TYPE_PREFERRED` | panel K10A bật sẵn | Có mode trong driver; QEAF chọn 120 Hz; chưa đo trên panel |
| Bluetooth | BTIF (`mtkbt_btif`) + `MTK_COMBO_BT` | `MTK_BTIF=y`, `MTK_COMBO_BT=y` | Built-in; cần firmware BT; chưa pair |
| Âm thanh | MT8192 AFE + MT6359 + CS35L41 | `SND=m` → `snd-soc-mt8192-afe`, `mt6893-mt6359`, `snd-soc-mt6359`, `mt6359-accdet`, `snd-soc-cs35l41*`, `snd-soc-core` (module) | Module được đóng gói và nạp theo thứ tự; chưa phát tiếng |
| GPU | Mali-G77: **chưa bind được**. Cây không có driver kbase/Mali; node DTS là `mediatek,mt6893-mali` còn Panfrost chỉ match `arm,mali-bifrost` / `arm,mali-valhall-jm` | `DRM_PANFROST=m` | `panfrost.ko` được nạp nhưng không có node nào khớp → báo UNSUPPORTED, không render node |
| Tự động xoay | SCP sensor hub → IIO accel | `MTK_TINYSYS_SCP_SUPPORT=y`, `MTK_SENSORHUB=y` | Có transport; SCP image do bootloader nạp (driver không `request_firmware`); chưa đọc mẫu |
| KVM | `CONFIG_KVM=y`, `VIRTUALIZATION=y` | defconfig | Có trong nhân; chưa chạy guest |

Không hỗ trợ (báo UNSUPPORTED, không giả lập): **NFC, camera, baseband**.

## Firmware

Driver Wi-Fi/BT hỏi các file dưới `mediatek/mt6893/` (ví dụ
`WIFI_RAM_CODE...`, `WIFI_MT6893_patch...`, `BT_RAM_CODE_MT6893...`,
`EEPROM_MT...`, `BT_Addr`). Repo **không chứa** các blob này. Lấy từ dump
vendor stock của chính máy:

```powershell
python scripts/mt689x_firmware.py --vendor D:\dump\vendor --dry-run
python scripts/mt689x_firmware.py --vendor D:\dump\vendor
```

Manifest ghi hash từng file đã copy. Thiếu family nào thì kernel/UI báo
`BLOCKED_FIRMWARE`, không báo READY.

## Build

```powershell
python scripts/build_mt689x.py                 # userspace ELF
python scripts/build_mt689x_kernel.py --config-only
python scripts/build_mt689x_kernel.py --jobs 12
python scripts/mt689x_firmware.py --vendor <dump>\vendor
python scripts/package_mt689x.py --kernel-dir \\wsl.localhost\Ubuntu-24.04\root\qeaf-mt689x\out\chopin
```

Bundle nằm ở `dist/mt689x/` gồm `vqeaf-init`, `qeaf-mt689x.cpio.gz`, `Image`,
dtb, `manifest.json` (sha256) và `README.txt`.

`--bootimg` chỉ dùng khi có `--reference stock-boot.img`: địa chỉ nạp và page
size được copy từ header stock. Không đoán các giá trị này.

## Chọn phiên lúc bật nguồn (MT689x)

Trong ~1,8 s đầu sau khi `/dev/dri/card0` xuất hiện, PID 1 lắng nghe các nút
cứng `/dev/input/event*`:

- giữ **Volume+** → ghi `denial` vào `/etc/qeaf/session`, chạy Denial Wayland
  nếu binary tồn tại;
- giữ **Volume−** → ghi `qeaf`, dùng shell QEAF;
- không nhấn → giữ nguyên lựa chọn cũ trong `/etc/qeaf/session` (mặc định QEAF).

Việc này nằm ở `platform/mt689x/mtk_session.c` (`mtk_session_boot_choose()`),
được gọi trước `try_denial_session()` trong `main_mt689x.c`. Không ghi phân
vùng, không đụng boot/misc. Khi không có binary Denial, QEAF luôn là fallback
và trạng thái được báo trung thực qua `mtk_session_note()`.

## Những gì chưa làm / rủi ro đã biết

- Chưa chạy trên máy: mọi dòng "READY" trong UI chỉ xuất hiện khi node tương
  ứng tồn tại lúc chạy; trên thiết bị chưa flash, không có dòng nào được đảm bảo.
- Firmware Wi-Fi/BT/ROM patch phải lấy từ máy. Không có cách nào hợp lệ để tự
  sinh. SCP thì khác: driver chỉ xác minh image đã được bootloader (LK) nạp vào
  SRAM, không gọi `request_firmware`, nên không có blob SCP trong bundle.
- Không có WPA supplicant trong image: kể cả khi `wlan0` xuất hiện, QEAF không
  tự kết nối mạng và không hiển thị "đã kết nối".
- Denial cần DRM master, libinput và socket Wayland. Script chỉ chạy khi binary
  tồn tại và `/etc/qeaf/session` ghi `denial`; nếu thoát, shell QEAF tiếp quản.
- Bootloader: máy stock khoá/verify boot. Mainline chỉ khởi động được qua
  bootloader mở (ví dụ U-Boot/fastboot boot tạm). Tài liệu này không hướng dẫn
  ghi đè partition stock.

## Kiểm chứng từ cây nhân (không phải phỏng đoán)

Các kết luận dưới đây đọc trực tiếp từ `7.3.3-mt6893-xiaomi-chopin` và từ
`.config` đã resolve của `chopin_defconfig` + fragment:

| Thành phần | Bằng chứng trong cây | Dạng build |
| --- | --- | --- |
| UFS MediaTek | `drivers/ufs/host/ufs-mediatek.c`: platform driver `.name = "ufshcd-mtk"`, không có match riêng cho `mt6893-ufshci` nên khớp qua `mediatek,mt8183-ufshci` | built-in |
| USB | `drivers/usb/mtu3/mtu3_plat.c` driver `mtu3`; DTS `mtu3_0@11200000` dùng `mediatek,mt6885-mtu3`, `dr_mode = "otg"`, `extcon = <&extcon_usb>`; Type-C là cell MFD `mt6360-tcpc` (platform driver) | built-in |
| Màn hình | `panel-k10a-bringup.c` match cả `l16_36_02_0b_dsc_vdo,lcm` (node đang bật) và `k10a_*`; DSI node `mediatek,mt6873-dsi` có trong driver và DTSI | built-in |
| Backlight/bias | `leds-lm36273.c` chỉ match `mediatek,I2C_LCD_BIAS` trong khi DTS ghi `mediatek,i2c_lcd_bias` → cần patch `0001-lm36273-...` (build script tự áp dụng) | built-in |
| conninfra | `conninfra/platform/consys_hw.c`: `.name = "mtk_conninfra"`; `drivers/misc/mediatek/connectivity/Makefile` dùng `obj-y` | built-in |
| WLAN | `wlan_drv_gen4m/os/linux/hif/axi/axi.c`: platform driver `.name = "wlan"`; `MODULE_NAME := wlan_6893_axi` nhưng `obj-y` khi `CONFIG_MTK_COMBO_WIFI=y` | built-in |
| Bluetooth | `bt/mt66xx/btif/btmtk_btif_main.c`: `.name = "mtkbt_btif"`; `obj-$(CONFIG_MTK_BTIF) += bt_drv_$(BT_PLATFORM).o` | built-in |
| SCP sensor hub | `sensor/2.0/sensorhub/Makefile`: `obj-$(CONFIG_MTK_SENSORHUB) += sensorhub.o` (tristate) | built-in vì `MTK_SENSORHUB=y` |
| Âm thanh | `sound/soc/mediatek/mt8192/Makefile` và `sound/soc/codecs/Makefile`; `SND=m` kéo `SND_SOC` và mọi codec thành module | module |
| GPU | defconfig: `CONFIG_DRM_PANFROST=m` (Mali-G77 = Valhall, Panfrost; Panthor là CSF nên không dùng) | module |

GPU **không thể bind** trên cây này: `panfrost_drv.c` chỉ có
`arm,mali-bifrost` và `arm,mali-valhall-jm`, còn node `mali@13000000` trong
`mt6893.dtsi` ghi `mediatek,mt6893-mali`; cây cũng không có driver kbase/Mali
nào khác. Vì of matching so khớp chuỗi tuyệt đối, không node nào khớp. UI và
`mt689x_caps.c` vì thế báo GPU `UNSUPPORTED` cho tới khi có binding Panfrost
thật (hoặc driver Mali) cho `mediatek,mt6893-mali`. `panfrost.ko` vẫn được
đóng gói và nạp — vô hại, nhưng không tạo render node.

Tên file `.ko` mà `mt689x_bringup.c` nạp, lấy từ Makefile:

```
snd-soc-core.ko
snd-soc-cs35l41-lib.ko
snd-soc-cs35l41.ko
snd-soc-cs35l41-i2c.ko
snd-soc-mt6359.ko
mt6359-accdet.ko
snd-soc-mt8192-afe.ko
mt6893-mt6359.ko
panfrost.ko
```

Vì connectivity và SCP là built-in, `/sys/module/...` không phải bằng chứng;
`mt689x_wifi.c` và `vqeaf_state.c` kiểm tra
`/sys/bus/platform/drivers/{wlan,mtk_conninfra,mtkbt_btif}` thay vào đó.
Census UFS kiểm tra `/sys/bus/platform/drivers/ufshcd-mtk/11270000.ufshci`
hoặc một đĩa SCSI thật.

## Kiểm thử trên host (không cần thiết bị)

```powershell
python scripts/test_mt689x_caps.py      # publish/report census
python scripts/test_mt689x_bootimg.py   # header boot v2 + offset payload
```

`test_mt689x_bootimg.py` dựng ảnh từ kernel/ramdisk/dtb tổng hợp bằng đúng
layout của header v2, rồi đọc lại và so từng trường; nó dùng boot.img stock
của violet chỉ để lấy page size/địa chỉ mẫu, không flash gì.
